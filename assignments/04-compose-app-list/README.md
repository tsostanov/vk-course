# Каталог приложений

[← К списку заданий](../../README.md)

Учебное приложение на Kotlin и Jetpack Compose. На главном экране — список приложений с иконками, описаниями и категориями. По нажатию открывается карточка с подробностями и витриной: девять приложений на трёх перелистываемых страницах.

Каталог постепенно дополняется по ходу курса. В заданиях 4–6 появились экраны, навигация, ViewModel и разделение на слои. В задании 7 добавлен Hilt, а в задании 8 — загрузка данных через Retrofit.

Данные и иконки теперь приходят с сервера, поэтому для загрузки нужен интернет. Пока запрос выполняется, виден индикатор. Если соединения нет или сервер вернул ошибку, можно повторить загрузку кнопкой «Повторить». Есть светлая и тёмная темы, положение списка сохраняется при пересоздании Activity.

## Задание 9: отмена корутин и рейтинги

В карточке приложения появилась кнопка «Установить». Она запускает симуляцию на три секунды: прогресс увеличивается на 5% каждые 150 мс. Во время установки кнопка показывает «Отменить»; нажатие отменяет `Job` и сбрасывает состояние. После завершения появляется неактивная кнопка «Установлено». Установка принадлежит `AppDetailsViewModel`, привязанной к записи навигации: поворот экрана её не прерывает, а выход из карточки отменяет. Это состояние текущей карточки, оно не сохраняется после её закрытия или завершения процесса.

Над списком есть кнопки «Последовательно» и «Параллельно». Нажмите сначала первую, дождитесь результата, затем вторую. Под каждой кнопкой отображается время в миллисекундах, а на карточках — рейтинг со звёздочкой. `CatalogApi.getRating(id)` имитирует запрос через `delay(1500)` и возвращает случайное число от 3,0 до 5,0. Каждый запуск получает новые значения. Пока выполняется загрузка, обе кнопки заблокированы.

Репозиторий реализует два способа: обычный suspend-вызов для каждого id и `async` + `awaitAll` внутри `coroutineScope`. Замеры и выводы находятся в [ANSWERS.md](../../ANSWERS.md). Для повторения замера на 12 приложениях с настоящими задержками:

```powershell
.\gradlew.bat :homework-04:testDebugUnitTest --tests '*AppRatingsBenchmarkTest' --rerun-tasks
```

Тест печатает строку `RATINGS_BENCHMARK`; она также сохраняется в XML-отчёте `build/test-results/testDebugUnitTest/TEST-com.example.vkcourse.applist.data.repository.AppRatingsBenchmarkTest.xml`. Остальные unit-тесты проверяют прогресс и отмену установки, повторный запуск, последовательность запросов, параллельность и отмену дочерних корутин при ошибке или отмене родителя.

Для задания 9 прошли 23 unit-теста и 11 UI-тестов на Pixel 10 (API 37), APK собирается. Lint: 0 ошибок и одно прежнее предупреждение `DataExtractionRules`.

## Задание 8: загрузка с сервера

В [CatalogApi.kt](src/main/java/com/example/vkcourse/applist/data/network/CatalogApi.kt) описаны GET-запросы Retrofit. Каталог загружается с `http://185.103.109.134/catalog`: сервер возвращает название, описание, категорию, id и ссылку на иконку каждого приложения. Gson преобразует JSON в DTO, а маппер — в модели, с которыми работает интерфейс. Иконки по `iconUrl` загружает Coil.

Hilt создаёт Retrofit в [NetworkModule](src/main/java/com/example/vkcourse/applist/di/NetworkModule.kt) и передаёт API сетевому источнику данных. Дальше используется прежняя цепочка: репозиторий → Use Case → ViewModel. Локальный список приложений заменён сетевым.

Для подробной информации есть `AppRepository.getAppDetails(id)`. Он возвращает отдельную модель с разработчиком, возрастным рейтингом, размером, скриншотами и полным описанием. Этот запрос пока не вызывается из интерфейса — по условию задания он понадобится позже.

При проверке сервера обнаружилось расхождение с условием: `/{id}` возвращает 404, а `/catalog/{id}` отдаёт подробности. Поэтому приложение сначала обращается к пути из задания, а при 404 пробует `/catalog/{id}`. Другие ошибки передаются вызывающему коду. Такое поведение проверяется тестами.

В манифест добавлено разрешение `INTERNET`. HTTP разрешён только для адреса учебного сервера в `network_security_config.xml`.

## Задание 7: внедрение зависимостей

Раньше `MainActivity` сама создавала источник данных и репозиторий, а для ViewModel была отдельная фабрика. Теперь эти зависимости создаёт Hilt.

Основные изменения:

- Добавлен `AppCatalogApplication` с `@HiltAndroidApp`, а Activity отмечена `@AndroidEntryPoint`.
- В [AppModule.kt](src/main/java/com/example/vkcourse/applist/di/AppModule.kt) два метода `@Binds` связывают интерфейсы репозитория и источника данных с их реализациями. Метод `@Provides` создаёт `GetCatalogAppsUseCase`.
- [AppCatalogViewModel](src/main/java/com/example/vkcourse/applist/presentation/AppCatalogViewModel.kt) получает Use Case через конструктор с `@Inject`. Для создания ViewModel используется `hiltViewModel()`.

Например, связь интерфейса репозитория с реализацией описана так:

```kotlin
@Binds
@Singleton
abstract fun bindAppRepository(impl: AppRepositoryImpl): AppRepository
```

Когда Use Case запрашивает `AppRepository`, Hilt передаёт ему `AppRepositoryImpl`. Сам Use Case не содержит аннотаций Hilt: его создание описано в DI-модуле, поэтому слой domain остаётся независимым от фреймворка.

## Как устроен код

Исходники находятся в `src/main/java/com/example/vkcourse/applist/`:

- `data` — Retrofit API, сетевой источник, DTO, мапперы и реализация репозитория.
- `domain` — модели, интерфейс репозитория и Use Case для получения каталога.
- `presentation` — Compose-экраны, навигация и ViewModel. Состояние экрана хранится в `StateFlow`, события snackbar передаются через `Channel`.
- `di` — модуль Hilt, в котором описано создание зависимостей.

ViewModel обращается к Use Case, тот — к интерфейсу репозитория. Репозиторий получает данные из сетевого источника и преобразует DTO в модели каталога. Запросы выполняются через `suspend`-функции и не блокируют интерфейс.

## Как запустить

1. Открыть корневую папку репозитория в Android Studio.
2. Установить Android SDK Platform 37 и выполнить Gradle Sync. Для сборки нужен полный JDK 25 — он указан в настройках проекта.
3. Выбрать модуль `homework-04` и запустить его на эмуляторе или устройстве с Android 7.0 и новее.

Собрать APK из PowerShell можно командой из корня репозитория:

```powershell
.\gradlew.bat :homework-04:assembleDebug
```

Готовый файл: `assignments/04-compose-app-list/build/outputs/apk/debug/homework-04-debug.apk`.

## Проверка

```powershell
# Сборка, unit-тесты и lint
.\gradlew.bat :homework-04:assembleDebug :homework-04:testDebugUnitTest :homework-04:lintDebug

# UI-тесты на запущенном эмуляторе или подключённом устройстве
.\gradlew.bat :homework-04:connectedDebugAndroidTest

# Дополнительно: проверить оба запроса на настоящем учебном сервере
.\gradlew.bat :homework-04:connectedDebugAndroidTest '-Pandroid.testInstrumentationRunnerArguments.class=com.example.vkcourse.applist.LiveCatalogApiTest' '-Pandroid.testInstrumentationRunnerArguments.liveApi=true'
```

В тестах с MockWebServer проверяются настоящие GET-запросы Retrofit, разбор JSON, путь с id, переход на `/catalog/{id}` при 404 и обработка ошибок сервера. Отдельно проверяются мапперы и состояния ViewModel: загрузка, успех, ошибка, повтор и пустой ответ.

UI-тесты используют тестовое API через Hilt, поэтому не зависят от доступности учебного сервера. Они проверяют каталог, навигацию, витрину, пересоздание Activity и кнопку повтора после ошибки.

`LiveCatalogApiTest` запускается только с аргументом `liveApi=true`: он обращается к настоящему серверу и проверяет каталог и подробности по id. При обычном запуске тестов эта проверка пропускается.

Для задания 8 прошли 12 unit-тестов, 9 UI-тестов и отдельный тест обоих запросов к настоящему серверу на Pixel 10 (API 37). APK собирается. Lint: 0 ошибок и одно предупреждение `DataExtractionRules` о настройках резервного копирования.

Если сборка сообщает, что не найден `jlink`, нужно проверить JDK для Gradle: среда Java из расширения VS Code может не содержать этот инструмент. После выбора полного JDK можно повторить команду с `--no-daemon`.

Для ручной самопроверки: открыть каталог с интернетом и убедиться, что показаны приложения с сервера, например QuickNote. Затем отключить интернет, перезапустить приложение и проверить сообщение об ошибке. Включить интернет и нажать «Повторить» — список должен загрузиться. Также можно открыть карточку, перелистать витрину и проверить сохранение позиции списка после поворота устройства.
