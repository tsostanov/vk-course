# VKCourse — практическое задание №3

В этом задании сделал два экрана на Kotlin и Jetpack Compose. На первом можно ввести текст и открыть вторую Activity, набрать номер или поделиться текстом. Приложение запускается с `MainActivity`, а `SecondActivity` открывается из неё через Intent.

## Запуск

1. Откройте проект в Android Studio и выполните Gradle Sync. Нужны Android SDK Platform 37 и устройство/эмулятор с Android 7.0 (API 24) или новее.
2. Используйте JVM, соответствующую `gradle/gradle-daemon-jvm.properties` (Java 25; Android Studio/Gradle могут загрузить её автоматически). Укажите установленный SDK в локальном `local.properties`.
3. Выберите модуль `app`, устройство и нажмите Run. Либо в PowerShell выполните:

   ```powershell
   .\gradlew.bat :app:assembleDebug
   & "$env:LOCALAPPDATA/Android/Sdk/platform-tools/adb.exe" install -r app/build/outputs/apk/debug/app-debug.apk
   & "$env:LOCALAPPDATA/Android/Sdk/platform-tools/adb.exe" shell am start -n com.example.vkcourse/.MainActivity
   ```

APK: `app/build/outputs/apk/debug/app-debug.apk`.

AGP 9.3.3, Gradle 9.5.0 и настройки SDK оставил прежними. Kotlin 2.2.10 уже встроен в AGP, поэтому добавил только Compose Compiler той же версии и включил `buildFeatures.compose`. Для библиотек использовал BOM 2025.08.00 и `activity-compose` 1.10.1. При подключении ориентировался на документацию по [встроенному Kotlin](https://developer.android.com/build/migrate-to-built-in-kotlin) и [компилятору Compose](https://developer.android.com/develop/ui/compose/setup-compose-dependencies-and-compiler).

Для тестов обновил Espresso до 3.7.0 и AndroidX Test JUnit до 1.3.0: старая версия Espresso не работала на эмуляторе Android 17. Исправление есть в [списке изменений AndroidX Test](https://developer.android.com/jetpack/androidx/releases/test).

## Ручная проверка

| Действие | Ожидаемый результат |
| --- | --- |
| Ввести `Привет, Android!` → «Открыть вторую Activity» | Открывается отдельная `SecondActivity`, отображается точный текст из extras. |
| Вернуться системной кнопкой/жестом «Назад» или кнопкой на втором экране | Возвращается первый экран, ввод сохранён. |
| Ввести `+7 (999) 123-45-67` → «Позвонить другу» | Открывается приложение набора номера с `+79991234567`. Звонок сам не начинается. Не нажимайте кнопку звонка при проверке. |
| Повторить с `8 999 123 45 67` и `(999)123-45-67` | Форматирование удаляется, номер подставляется в набор номера. |
| Ввести текст → «Поделиться текстом» | Открывается системный chooser «Поделиться через…» с доступными приложениями; передаются `ACTION_SEND`, `EXTRA_TEXT` и `text/plain`. Заголовок и оформление могут зависеть от Android. Отменить отправку можно через «Назад». |
| Оставить поле пустым, затем ввести только пробелы; проверить все три кнопки | Ошибка в интерфейсе, внешнее приложение/вторая Activity не открываются. |
| Ввести `abc`, `++79991234567`, `(9991234567`, `123#`, `12` → набор номера | Сообщение о некорректном номере, Intent не отправляется. |
| Повернуть устройство после ввода и ошибки | Ввод и сообщение сохраняются, содержимое доступно с прокруткой и открытой клавиатурой. |

В номере должно быть от 3 до 15 цифр. Можно добавить плюс в начале, пробелы, парные скобки и дефисы. Перед набором пробелы, скобки и дефисы убираются. Буквы, USSD-команды и добавочные номера не принимаются. Проверяется только формат номера. Текст передаётся как введён, вместе с пробелами по краям, но пустую строку или одни пробелы отправить нельзя.

Если приложение для набора номера не найдено или система запрещает запуск, на экране появляется сообщение. Перед отправкой текста проверяю, есть ли подходящее приложение; для этого добавил `<queries>` в манифест. Разрешение на звонки не нужно, поскольку используется только набор номера.

Если вторая Activity открылась без текста, она показывает ошибку и кнопку возврата. Это проверяется в `SecondActivityTest`. Через ADB открыть её нельзя: в манифесте стоит `exported=false`. Отсутствие нужных приложений проверяю в тестах с подменой запуска Intent, без отключения системных приложений эмулятора.

## Автоматические проверки

```powershell
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
# Требуется запущенный эмулятор или подключённое устройство:
.\gradlew.bat :app:connectedDebugAndroidTest
```

В тестах проверяю ввод, переход между Activity, возврат и сохранение данных при пересоздании экрана. Также проверяю параметры Intent и сообщения об ошибках. Для набора номера и отправки текста тест нажимает кнопку, но сохраняет Intent вместо запуска другого приложения. Настоящий набор номера и системное окно отправки проверены отдельно через интерфейс эмулятора.

Отчёты: `app/build/reports/tests/testDebugUnitTest/index.html`, `app/build/reports/androidTests/connected/debug/index.html`, `app/build/reports/lint-results-debug.html`.

Фактические результаты проверки этой версии перечислены в описании Pull Request.
